# Shift IME Toggle + JIS/US配列リマップ (Win11 / AutoHotkey v2)

左Shiftキーを押すとIMEオフ（半角/直接入力）、右Shiftキーを押すとIMEオン（かな入力）に切り替える常駐ツールです。
USキーボードでも動作します。あわせて、JIS配列ノートPC本体とUSキーボードを併用する場合向けに、
`Win+F12` で記号キーの配列をJIS⇔USに切り替えるリマップ機能も入っています。
さらに、IMEがONだと効かなくなる nvim の `jk`→`Esc` を、Warp上で機能させる補助も入っています。

## 前提となる使い方

Windowsの「入力方式」は**日本語IME1本だけ**を使う想定です（英語入力用に別の入力方式へ切り替える運用ではない）。
日本語IMEを開いたまま英字を打つ・閉じて直接入力する、をShiftキーで行き来するイメージです。
英語入力用に「English(US)」など別の入力方式に切り替えて使っている場合、切り替え中はIME自体が存在しないため
このツールのIME ON/OFFは効きません（その場合は別方式の検討が必要です）。

## 仕組み

### 1. Shift IME切り替え
- `LShift` / `RShift` は AutoHotkey が仮想キー（VK_LSHIFT / VK_RSHIFT）で判定するため、
  物理キーボードの配列（US/JIS）に依存しません。専用の「かな」キーは一切使いません。
- IMEのON/OFFはキー送信ではなく、`imm32.dll` の `ImmSetOpenStatus` をAPIで直接呼び出して
  切り替えています。MS-IME・Google 日本語入力など IMM32 互換のIMEであれば、
  アプリやキーボード設定に関係なく確実に効きます。
- ホットキーには `~` を付けているため、Shiftキー本来の機能（大文字入力、Shift+矢印など）は
  そのまま生きたまま、追加でIME切り替えが発動します。
- フォーカスのある子コントロール（エディットボックス等）を `GetGUIThreadInfo` で正確に取得してから
  IME状態を切り替えるため、ウィンドウによって効かないという問題が起きにくくなっています。

### 2. JIS ⇔ US 記号キーリマップ（`Win + F12` でトグル）
- Windowsのキーボードレイアウト設定は常に1つ（このPCではJIS 106/109）で、繋いだ物理キーボードを
  自動判別しません。そのためUSキーボードを繋いだままJISレイアウト設定だと、記号キー
  （`` ` `` `2@` `6^` `7&` `8*` `9(` `0)` `-_` `=+` `[{` `]}` `\|` `;:` `'"`）の印字と実際に
  入力される文字がズレます。
- スキャンコード（物理キー位置。レイアウトに依存しない）を直接フックし、USモードが有効なときだけ
  USキーボードの印字通りの文字を送出することでズレを解消します。
- デフォルトはOFF（JIS配列＝ノートPC本体のキーボード用）。USキーボードを接続したら `Win+F12` でON、
  外して本体キーボードに戻すときはもう一度 `Win+F12` でOFFにしてください。タスクトレイのメニューからも
  ON/OFFを切り替えられ、現在の状態はメニューのチェック印とアイコンのツールチップで確認できます。
- 制限事項: Shiftとの組み合わせのみ対応しています。`Ctrl+[` のような制御用ショートカットは
  現在のOSレイアウト（JIS）通りに動作します。JIS特有の「無変換/変換/かな/ろ」キーはUSキーボードに
  物理的に存在しないため対象外です。

### 3. `jk` で Esc + IME OFF（nvim用 / Warp）

nvim には `inoremap jk <Esc>`（`lua/config/keymaps.lua`）を設定していますが、**IMEがONの間は
`j` も `k` もIMEのローマ字変換バッファに吸われて nvim まで届かない**ため、このマッピングが効きません。
nvim 側からは「何も押されていない」のと同じなので、nvim の設定では直せません。
そこでIMEがONのときだけAHK側で `jk` を横取りし、IMEをOFFにしてから `Esc` を nvim に送ります。

#### 発動条件（すべて満たしたときだけ）

1. フォアグラウンドが `JK_TARGET_PROCESSES` のプロセス（既定は Warp のみ）
2. nvim が「今この瞬間、IMEさえ無ければ自分で `jk` を処理していた」と言っている
3. IMEがON

IMEがOFFのときは一切介入しません。nvim側の `jk` マッピングがそのまま効きますし、
ノーマルモードの `j` 移動にも遅延が出ません。

#### nvim 側との連携

条件2は AHK からは絶対に見えません。Warp のウィンドウタイトルは Warp が独自に付けており
（AIタスク名やカレントディレクトリ）、中で動いているプログラムを表さないためです。
そこで nvim 設定側（`%LOCALAPPDATA%\nvim`）に `lua/config/ime_jk.lua` を置き、
状態を `%TEMP%\nvim_ime_jk_state` に書き出してもらっています。

- 内容は `1 <pid>`（横取りしてよい）または `0`。pid を添えるのは、nvim が異常終了して
  `1` のまま残った場合に AHK 側が「そのpidはもう居ない」と気づけるようにするためです。
- nvim 側の判定はモードではなく `maparg` で**その場に実際に `jk` マッピングがあるか**を見ています。
  こうしておくと、Claude / Cursor CLI / lazygit のターミナルにだけ `jk` を張らない
  `keymaps.lua` の除外が、二重管理なしでそのまま AHK 側にも効きます
  （それらの端末に `Esc` を送ると CLI が落ちるため重要）。
- **macOS では何もしません。** `ime_jk.lua` の `setup()` は `config.platform.is_windows` で
  早期 return します。Mac 側は Karabiner-Elements が同じことを担当しており、
  この仕組みは一切干渉しません。

#### 動き

`j` は押した時点では送らずに保留し、続く1キーを見てから判断します。`k` なら Esc、
それ以外なら「`j` → そのキー」の順で改めて送出するので入力順は崩れません。
待ち時間は `JK_TIMEOUT`（既定300ms、nvimの `timeoutlen` と同値）です。
先に `j` を通してしまうとIMEの変換バッファに `ｊ` が残り、後から消す手段が不確実になるため、
必ず保留してから判断しています。

#### 調整用の定数（`shift_ime.ahk`）

| 定数 | 既定 | 意味 |
|---|---|---|
| `JK_TARGET_PROCESSES` | `["warp.exe"]` | 対象アプリ。別のターミナルでも使うなら exe 名を足す |
| `JK_TIMEOUT` | `300` | `k` を待つ猶予(ms) |
| `JK_IME_OFF_DELAY` | `20` | IME OFF後 `Esc` までの待ち(ms)。効かないときはまずここを50〜80に上げる |
| `JK_STATE_FILE` | `%TEMP%\nvim_ime_jk_state` | nvim との受け渡しに使うファイル |

#### 制限事項

- IMEがONで挿入モードの間、`j` の表示が最大300ms遅れます（続くキーを待つため）。
  「じゃ」は `a` を押した瞬間に確定表示されます。
- Warp の別タブへ切り替えたときに状態を落とせるかは、Warp がフォーカス通知（DECSET 1004）を
  nvim に送るかどうかに依存します。送られない場合、挿入モードのまま別タブへ移ると
  そのタブでも `jk` が効いてしまいます。

## ファイル

- `shift_ime.ahk` … AutoHotkey v2 ソースコード（これ1つだけ。exeは作りません。理由は後述）

## 前提: AutoHotkey v2 の導入

`winget install AutoHotkey.AutoHotkey` で導入済みです。
インタプリタ本体は `%LOCALAPPDATA%\Programs\AutoHotkey\v2\AutoHotkey64.exe` にあります。

## 使い方

`shift_ime.ahk` をダブルクリック（AutoHotkey v2 に関連付け済みなら）、
または以下で常駐します。タスクトレイのアイコンから「終了」を選ぶと終了します。

```powershell
& "$env:LOCALAPPDATA\Programs\AutoHotkey\v2\AutoHotkey64.exe" "shift_ime.ahk"
```

## Windows起動時に自動実行したい場合

1. `Win + R` → `shell:startup` → Enter でスタートアップフォルダを開く
2. そこに新規ショートカットを作り、以下を設定する
   - リンク先: `%LOCALAPPDATA%\Programs\AutoHotkey\v2\AutoHotkey64.exe "<このリポジトリのパス>\shift_ime.ahk"`
   - 作業フォルダー: このリポジトリのパス

## exe を配布・コミットしない理由

以前は `Ahk2Exe` でコンパイルした `shift_ime.exe` を同梱していましたが、廃止しました。

- Ahk2Exe の出力は「未署名 + 世界に1つしかない低流通のバイナリ + キーフックと `SendInput` を含む」
  という構成になるため、Microsoft Defender の機械学習判定で `Wacatac.B!ml` として
  誤検知されます（実際に検知・インシデント起票されました）。
- さらに `.ahk` を修正して再コンパイルするたびに exe のハッシュが変わるため、
  ハッシュ単位で許可リストに登録してもらっても、次のビルドで必ず外れます。

`.ahk` を `AutoHotkey64.exe`（多数のユーザーが使う既知のバイナリ）に渡して実行すれば、
検知対象になる自作バイナリ自体が存在しなくなります。機能は完全に同じです。
`*.exe` は `.gitignore` 済みです。
